# 备份与恢复（含 TLS 部署）

> 适用：智能知识中心 V2.0 · PostgreSQL 部署形态 · 2026-09-29
> 对应商用评估框架一票否决项：数据备份（RPO/RTO）、传输加密（TLS）、审计保留

## 一、双层级自动备份（默认已启用）

| 层级 | 内容 | 频率 | 保留 | 作用 |
|---|---|---|---|---|
| db-only | 仅数据库快照（约 0.5MB） | 每 1 小时 | 72 份（3 天） | **数据 RPO ≤ 1 小时** |
| 全量 | 数据库 + 全部附件（GB 级） | 每 6 小时 | 7 份 | 完整恢复能力 |

- 产物在 `backend/data/backups/`：`backup-db-*.zip.enc`（小时级）与 `backup-*.zip.enc`（全量），**默认 AES-256-GCM 加密**。
- 手动备份：设置 → 备份还原 → 创建备份（全量）。
- 配置开关（.env）：`AUTO_BACKUP_ENABLED` / `AUTO_BACKUP_INTERVAL_HOURS` / `BACKUP_DB_INTERVAL_HOURS`（设 0 关闭小时层）/ `BACKUP_DB_KEEP_COUNT` / `AUTO_BACKUP_KEEP_COUNT`。

## 二、加密密钥管理（重要！）

- 密钥自动生成于 `backend/data/.backup-key`（64 位 hex，权限仅当前用户）。
- **密钥文件不在任何备份包里**。异地容灾请把该文件另行抄录保管（密码管理器/U 盘）。
- 也可用 `BACKUP_ENCRYPTION_KEY`（64 位 hex）显式指定，多机统一密钥时用。
- 关闭加密：`BACKUP_ENCRYPT=false`（不建议，备份落在网络盘时尤其不建议）。

## 三、异地复制

`.env` 设置（必须是绝对路径）：

```
BACKUP_OFFSITE_DIR=Z:\aikb-backups     # 网络盘
# 或第二块本地盘：BACKUP_OFFSITE_DIR=D:\aikb-backups
```

每次备份完成后自动复制一份过去；目标不可达只记录告警，不影响本地备份。

## 四、恢复流程（已演练，见第六节记录）

```bash
# 1) 解密（本机恢复；换机恢复加 --key 指定异地保管的密钥文件）
node scripts/decrypt-backup.mjs backend/data/backups/backup-db-XXXX.zip.enc 解密输出.zip --key backend/data/.backup-key

# 2) 从 zip 中取出 pgdump.dump（任意解压工具）

# 3) 恢复到目标库（管理员）
psql -U postgres -c "CREATE DATABASE aikb_new OWNER fqy;"
pg_restore -U fqy -d aikb_new --no-owner pgdump.dump

# 4) 切换 .env 的 DB_NAME=aikb_new 并重启后端
```

附件恢复：解压全量备份中的 `uploads/` 回 `backend/data/uploads/`。

## 五、TLS（HTTPS）部署

```bash
# 1) 生成内网证书（Git Bash；10 年有效，SAN 含 localhost/主机名/127.0.0.1）
./deploy/tls/gen-cert.sh [局域网IP] [附加域名]

# 2) 员工机信任证书（每台一次，管理员 PowerShell）
certutil -addstore -f Root deploy\tls\aikb-server.crt

# 3) 启动统一 HTTPS 入口（8443 → 前端 5274 / 后端 3101）
node scripts/https-proxy.mjs

# 4) .env 设置并重启后端（Secure Cookie 仅经 HTTPS 传输）
COOKIE_SECURE=true
```

实测（2026-09-29）：TLSv1.3 / TLS_AES_256_GCM_SHA384；HTTPS 下登录 201、业务请求 200、前端页面 200。

## 六、审计日志保留与只追加

- 应用层无任何审计删除入口；PostgreSQL 层已 `REVOKE UPDATE, DELETE`（迁移 1788500000000），`audit_logs` / `ai_call_logs` / `client_errors` 三表只可 INSERT/SELECT——即使未来代码出 bug 也改不了历史审计。
- 保留 ≥180 天由"不自动清理"保证；按月归档（可选）：
  `psql -c "\copy (SELECT * FROM audit_logs WHERE createdAt >= '2026-09-01' AND createdAt < '2026-10-01' AND id NOT IN (SELECT id FROM audit_logs WHERE createdAt < '2026-04-01')) TO audit-2026-09.csv CSV HEADER"`
  归档文件与备份一并异地存放。

## 七、恢复演练记录（RTO 实测）

| 日期 | 源备份 | 步骤 | 耗时 | 校验 |
|---|---|---|---|---|
| 2026-09-29 | backup-db-2026-09-29T12-35-40.zip.enc（0.5MB） | 解密 0.4s + pg_restore 1.3s | **1.7s** | customers 195 / documents 456 / quotations 10 / projects 10 / audit_logs 2201 全部与主库一致 |

## 八、双因素认证（TOTP）

- 每个账号自助绑定：设置 → 安全设置 → 开始绑定（认证器 App 手动输入密钥）→ 输入 6 位码启用。
- 启用后登录页在密码之后要求动态码；关闭需密码 + 动态码双确认。
- 管理员账号建议必开。
