## 一、系统总览

### 1.1 系统定位

面向装备制造（矫直设备）销售与技术团队的一体化业务 + 知识管理平台，主链路为：

```
客户 → 需求 → 方案 → 报价 → 合同 → 项目 → 售后
              ↑（知识中心：方案库 / 产品库 / 供应链 / 计算工具 / AI 助手 支撑全链路）
```

运行模式：`single`（单机个人版，自动登录管理员）/ `team`（团队版，RBAC + 审批）。当前部署为 single 模式。

## 二、业务管理模块解读

### 2.1 工作台 WorkflowWorkbench（`/`）

- **布局**：KPI 卡片行（6 卡）→ 六阶段业务流水线网格（每列 = 阶段头 + 最近 4 张卡片 + "还有 N 项"）→ 三列卡片（转化漏斗 / 近 6 月报价趋势 / 最近动态时间线）。
- **KPI 字段**：本月需求 `monthRequirements`、待完善 `needsAttention`、进行中项目 `activeProjects`、客户总数 `customers`、本月报价额 `monthQuoteAmount`、本月成交额 `monthWonAmount`。
- **流水线卡片**：标题（多模块字段兜底链 `title/name/contractNo/ticketNo/...`）、客户 `customerName`、日期 `createdAt`。
- **操作**：阶段头/卡片点击跳对应模块列表；漏斗与趋势空态提供"去创建客户 / 从需求开始"引导。
- **发现问题**：
  1. 六模块计数各拉一次 `pageSize:200` 列表——**总量超 200 时计数封顶失真**，且仅为取计数就并发拉 6 个全量列表。
  2. 各模块请求 `.catch(() => ({list:[]}))` 静默吞错，单模块失败用户无感知。
  3. `extractList` 兼容 array/`list`/`items` 三种返回形状 → 后端列表接口返回结构不统一。

### 2.2 客户中心 Customers（`/customers`）

- **布局**：统计卡（5 卡）+ DataTable；搜索/状态筛选/导入/导出/新建/批量栏在顶栏；详情 Drawer、新建编辑 Modal；双击行进 360。
- **表格列**：客户编号 `customerCode`、客户名称 `name`（可排序）、简称 `code`、类型 `customerType`、行业 `industry`、等级 `level`（A/B/C/D 配色）、业务状态 `businessStatus`、区域 `region`、负责销售 `salesPerson`。
- **新建/编辑弹窗**（15 字段）：客户编号（留空自动生成）、客户名称*、客户简称、客户类型、所属行业*、客户等级、业务状态（默认活跃）、所属区域、企业规模、统一社会信用代码、注册地址、企业网址、负责销售、首次合作日期、可见性。
- **联系人子表单**（可多行）：姓名、职务、部门、手机、邮箱、微信/飞书、决策角色、主联系人——**均无必填与格式校验**。
- **筛选**：关键词（300ms 防抖）+ 业务状态下拉（潜在/合作中/已停用，选项硬编码）。
- **操作**：行操作（360/查看/编辑/删除含级联预检）；批量改类型/行业/等级/业务状态/区域 + 批量删除；Excel 导入导出。
- **发现问题**：
  1. **字段命名反语义**：`code` 存"简称"、`customerCode` 存"编号"，极易混淆。
  2. `initialForm` 含 `status` 与 `description`，弹窗中**无对应控件**——备注用户看不到也改不了，编辑时被静默回写。
  3. 统计卡"流失"取值 `c?.lead`（lead=线索），字段与文案语义不符。
  4. 状态筛选选项硬编码，未复用 types 中的 options 常量体系。
  5. 大量 `(row as any)`：`Customer` 类型缺 `level/businessStatus/region/salesPerson` 等字段定义。
  6. 联系人手机/邮箱无格式校验。

### 2.3 客户360档案 Customer360（`/customers/:id`）

- **布局**：客户头卡（名称/行业/规模/编码/地址 + 联系人条 + 累计报价额）→ 统计周期切换（全部/本年/本季/本月）→ 9 张统计卡 → **10 个页签**（概览/需求/方案/报价/合同/文档/项目/售后/沟通记录/AI 洞察）；支持 `?tab=` 深链。
- **各页签核心字段**：
  - 项目：编号 `projectNo`、名称、流程阶段 `dealStage`、类型（新客户/复购/扩展）、文档数、创建时间
  - 需求：编号、项目名称、识别状态 `specStatus`、优先级、创建时间
  - 方案：编号、项目名称、版本、状态
  - 报价：编号、金额、状态、时间
  - 合同：编号、标题、金额、状态、签订日期
  - 文档：文件名、来源（按 link 的 requirementId/proposalId/… 推断）、阶段、类别、版本、上传人、时间
  - 售后：工单号、标题、类型、设备型号、优先级、状态、创建时间
  - 沟通记录：方式、时间、内容、双方参与人、关注点、下一步
  - AI 洞察：相似客户（相似度/匹配原因/交叉销售机会）、配套推荐（懒加载）
- **发现问题**：
  1. **周期切换只作用于统计卡**，页签表格与"累计报价额"不随之过滤——同一页两套口径。
  2. 所有页签**一次性全量渲染，无分页/排序/搜索**。
  3. 手写 `<table>`，未复用 DataTable（无加载态/排序一致性）；方案页签缺 `overflow-x-auto`。
  4. AI 洞察返回字段为 snake_case（`match_reasons` 等），与全站 camelCase 不一致。
  5. 错误态"重试"按钮实际跳回客户列表，并非重试。

### 2.4 客户需求 Requirements（`/requirements`）

- **布局**：统计卡（6 卡）+ DataTable；新建/编辑 Modal；`?highlight=id` 重定向详情；状态筛选同步 URL。
- **表格列**：需求编码 `requirementNo`、客户名称 `customerShortName`（缺失显示"未关联"）、项目名称 `title`、需求类型 `requirementType`、需求来源 `category`、产品类型 `templateCategory`、优先级 `priority`、状态 `status`、创建时间。
- **新建/编辑弹窗**：需求编码（只读）、需求类型、项目名称*、关联客户*（服务端搜索选择）、需求来源、优先级（默认中）、产品类型（未指定可由 AI 识别）、状态、联系人/电话/邮箱（无格式校验）、需求描述、需求资料上传（**新建时 entityId 为空**）。
- **操作**：查看/生成方案/编辑/导出识别文件 PDF/删除（含预检）；批量改类型/来源/优先级 + 批量删除；导入导出。
- **发现问题**：
  1. `category` 字段名存"需求来源"，与 `requirementType`（需求类型）语义易混；详情页另有一套中文键文案映射 `SOURCE_CATEGORY_LABELS`——**同一字段两套文案**。
  2. 联系电话/邮箱无格式校验。
  3. 新建阶段上传资料依赖组件兜底（entityId undefined）。

### 2.5 需求详情 RequirementDetail（`/requirements/:id`）

- **布局**：DetailLayout（编号/标题/状态流转下拉/操作区）+ 6 页签：基本信息、结构化参数、关联方案（含历史相似方案匹配）、关联资料、计算记录、需求记录（Timeline）。另有回复草稿 Drawer、计算工具 Drawer、新增记录 Modal。
- **关键字段**：基本信息 13 项（编号/客户/类型/来源/联系人/产品类型/优先级/状态/解析状态 `specStatus`/版本/解析时间/描述/变更原因）+ AI 分析摘要；结构化参数来自 `structuredSpec` JSON（兼容新旧两种结构）。
- **操作**：结构化识别、生成客户回复（微信/邮件双模板）、计算工具、AI 分析跳转、识别文件导出（PDF/Word）、新建方案、状态流转自动留痕。
- **发现问题**：
  1. **同一导出接口两份实现且鉴权不一致**：列表页用 Cookie（`credentials:'include'`），详情页用 localStorage Bearer token；导出文件名也不一致（`{编号}_需求信息文件.pdf` vs 固定 `需求识别文件.pdf`）。
  2. 计算工具下拉**硬编码 5 项**，与 CalcTools 页的模板驱动数据源脱节。
  3. `structuredSpec` JSON 字符串存储 + 多处 try/catch 解析，历史包袱。
  4. 状态流转日志 `.catch(()=>{})` 静默失败。

### 2.6 方案 Proposals（`/proposals`）

- **布局**：统计卡（5 卡）+ 双 Tab（方案列表 / 智能推荐三步向导）；新建编辑 Modal、AI 生成 Modal、详情 Drawer。
- **表格列**：方案编码、客户名称、项目名称、类型 `proposalType`（整机设备/零部件/技术/商务/解决方案）、版本 `version`、状态。
- **表单字段**：方案编号（只读）、方案类型、项目名称（仅编辑可改）、客户（只读带出）、产品描述、技术要求、方案正文（编辑态可从 Word/PDF 导入解析）、方案资料（仅编辑态）。
- **操作**：查看/生成报价/导出 Word/编辑/删除；批量改类型/状态；AI 生成；智能推荐（选需求→匹配标准方案→生成草稿）。
- **发现问题**：
  1. **列表 Tab 无"新建方案"按钮**；新建弹窗项目名称 disabled 且必填——不带 `requirementId` 直接进入时**新建永远不可用**。
  2. 无提交审批 API，状态只能靠批量编辑裸改枚举。
  3. `JSON.parse(structuredSpec)` 无 try/catch，脏数据直接渲染崩溃。

### 2.7 报价 Quotations（`/quotations`）

- **布局**：统计卡（6 卡）+ DataTable；编辑 Modal（明细行编辑器）、AI 建议 Modal、详情 Drawer（成本/毛利分析）。
- **表格列**：报价编码、客户名称、项目名称、金额 `amount`、状态、创建时间。
- **表单字段**：报价编码（只读，继承方案）、总金额（明细自动汇总，只读）、项目名称、客户（只读）、关联方案（只读必填）、明细行 items[]（名称/数量/单价，至少 1 条；名称支持产品库联想带出参考价）、备注、报价资料。
- **操作**：查看/转合同/编辑/删除；批量改状态/删除；AI 报价建议（可预览采纳）；详情内供应商比价跳转、打印/导出 PDF；毛利低于 15% 告警。
- **发现问题**：
  1. **无新建入口**，只能从方案带参派生。
  2. **状态口径三处不一致**：筛选器 6 种（含已发送/已成交/已失单），批量条只有 4 种，且 approved 文案"已审核" vs 筛选器"已批准"。
  3. 关联方案名称回显全量拉 `proposalApi.list()`。
  4. 「查供应商比价」按钮跳 `/suppliers/compare`——**该路由不存在（死链）**。

### 2.8 合同 Contracts（`/contracts`）

- **布局**：统计卡（6 卡）+ DataTable；编辑 Modal、详情 Drawer。**唯一缺 PageHeader 的单据页**。
- **表格列**：合同编号、合同标题、客户、合同金额、状态、签订日期。
- **表单字段**：合同标题*、合同金额、关联报价（EntityPicker，可继承编号）、关联客户（只读）、签订/生效/到期日期、付款条款、交付条款、合同资料。
- **操作**：查看/转项目/编辑/删除；**审核通过**（唯一有显式状态流转 API 的单据）；批量改状态/删除。
- **发现问题**：
  1. 详情 Drawer **无加载态与失败态**（其余页面均有）。
  2. 编辑既有合同时"关联客户"只显示派生预填值，编辑态显示占位文案而非真实客户。
  3. 批量改状态无任何流转约束（可"已完成→草稿"逆向跳）。

### 2.9 售后 AfterSales（`/after-sales`）

- **布局**：统计卡（6 卡）+ 状态 Tab 条 + DataTable；新建编辑 Modal、详情 Drawer。**五个单据页中唯一保留新建入口**。
- **表格列**：工单编号、标题、类型（故障报修/定期保养/备件需求/客户回访）、客户、设备型号、优先级、状态。
- **表单字段**：工单标题*、工单类型、优先级、客户、设备型号、故障描述、指派工程师（自由文本）、状态（仅编辑态）、处理过程、使用备件、满意度（1-5）、回访日期、回访记录、售后资料（挂客户，需 customerId）。
- **操作**：新建/编辑/删除；批量改类型/优先级/状态；详情内**转备件需求**、**转知识库 FAQ**（数据回流）。
- **发现问题**：
  1. **状态 Tab 缺"已派单 assigned / 已关闭 closed"**，而表单和批量编辑支持这两状态 → 筛不到。
  2. 指派工程师为自由文本，无人员选择器。
  3. 新建未选客户时资料上传区不可用且无提示。

### 2.10 项目 Projects（`/projects`）

- **布局**：统计卡（6 卡）+ DataTable；编辑 Modal（含阶段/风险行编辑）、详情 Drawer（含任务区）。
- **表格列**：项目编号、客户、项目名称、类型、进度（进度条）、健康度（绿/黄/红）、状态、周期。
- **表单字段**：项目编码（只读）、项目名称*、客户（只读）、状态、项目类型、流程阶段 `dealStage`（选择即保存不走表单）、开始/结束日期、描述、项目阶段 stages[]（名称/说明/起止/状态）、风险项 risks[]（标题/描述/应对/等级）、项目资料（按阶段自动归类）。
- **操作**：查看/编辑/转售后工单/删除；流程阶段即时切换（含回滚）；标记成交引导沉淀标准模板（知识飞轮）；批量编辑/删除；任务增删改。
- **发现问题**（本页问题最集中）：

  2. `dealStageOptions`（8 项）不含 `contract_signed`，但从合同派生时恰好设为 `contract_signed` → 下拉选中值不在选项列表；批量条的阶段选项却包含它 → 两处选项集不一致。
  3. 同一阶段多处中文标签不一致：`quotation_reviewed` "报价定稿" vs "报价审核"、`submitted` "已发送客户" vs "已提交客户"、`lost` "已结束" vs "已流失"。
  4. 新建弹窗有"状态"下拉但提交时被 delete，选择无效且无提示。
  5. `managerId` 自由文本，详情页显示原始 ID 而非姓名。
  6. 进度/健康度在列表展示但表单无编辑入口。

## 三、知识中心模块解读

### 3.1 业务资料 Documents（`/documents`）

- **布局**：统计卡 + 左侧三级分类导航树（可拖宽/翻页/增删改名排序）+ FilterPanel（内容状态/文件格式）→ 右侧 DataTable；上传/编辑/关联/移动/批量弹窗、详情抽屉、回收站抽屉、全链路回查抽屉、文件预览。
- **表格列**：文件名、资料所属 `ownerModule`、类型 `category`、关联客户、大小、状态、上传时间。
- **上传弹窗**：文件、标题*、资料类型（大类/子类/孙类平铺）、可见性（公开/部门/私有）。关联弹窗：对象类型（客户/需求/方案/报价/项目/方案库）+ 对象选择 + 扮演角色（来源/交付物/参考）。
- **操作**：上传（弹窗/直传/拖拽批量，并发限 2）、预览、编辑、移动分类、关联业务对象、下载、软删除、批量移动/删除、回收站还原/彻底删除、导航分类维护。
- **分类体系**：`DOC_CATEGORY_OPTIONS / DOC_SUBCATEGORY_MAP / DOC_GRANDSUB_MAP`（客户视图为 `CUSTOMER_DOC_*`），另注入「产品资料」大类（子类=产品列表，category 存 `product:产品名`）。
- **发现问题**：
  1. **单文件 2212 行**，一个组件承担双 scope、导航树管理、回收站、链路回查等十余项职责，状态变量 30+。
  2. 批量移动/删除为 **for 循环串行逐条调接口**，无批量 API，中途失败无回滚。
  3. 同名校验只查当前页数据，跨页同名检测不全。
  4. **导航分类的增删/改名/排序/隐藏全部存 localStorage**，仅本机可见，多端不一致。
  5. 删除导航分类不检查分类下是否有文档，文档会失去导航归属。

### 3.2 客户资料 CustomerDocs（`/customer-docs`）

- **布局**：统计卡 + 左侧「全部 → 公司（分页）→ 业务阶段」树 → 右侧表格；**只读**，仅支持批量改分类。
- **列表字段**：文件（含版本标记）、来源（按 link 的 requirementId/proposalId/quotationId/projectId/contractId 推导）、类型（输入/输出/参考 linkRole）、阶段（stage · category）、上传人、时间。
- **阶段桶**：`STAGE_BUCKETS` 9 个桶（需求管理/分析文档/技术方案/报价管理/合同管理/项目管理/售后管理/原始资料/其他），用正则把三代历史 stage 取值归一。
- **发现问题**：
  1. `bucketOf` 正则归一**顺序敏感**：含「需求」字样的 project 阶段值会误入需求桶；三套历史取值混合存在映射遗漏风险。
  2. 客户明细来自 `get360` 一次性全量返回 + 纯前端过滤，无分页。
  3. 批量勾选数组跨视图共享，可能产生「看不见但已选」的项。

### 3.3 知识资料 KnowledgeBase（`/knowledge`）★核心页

- **上传弹窗**：文件区 + 待传列表 + 大类按钮组 + 子分类选择（自定义大类下可现场新建子类）；标题即文件名，无标签字段。
- **操作**：上传、手动重新索引、预览、移动分类、下载、删除（软删进回收站 30 天）、批量改分类/删除、导航分类维护。
- **分类体系**（8 个内置大类）：

| 大类 | 子类 |
|---|---|
| FAQ常见问题 | 选型FAQ、技术参数FAQ、工艺FAQ、价格/商务FAQ、交期/物流FAQ、售后/质保FAQ |
| 技术知识 | 技术原理、工艺知识、材料知识、设备结构、电气控制、液压/润滑、行业动态 |
| 标准规范 | 国家标准、行业标准、企业标准、国际标准、客户特殊规范 |
| 模板表格 | 技术协议模板、验收标准模板、测试报告模板、现场勘测表、计算表格、参数对照表 |
| 培训资料 | 产品手册、培训教材、操作手册、维护手册、安全规程 |
| 常用提交资料 | 产品说明书、合格证、装箱单、出厂检验、随机文件 |
| 故障排除 | 故障排除 |
| 其他 | 其他 |

  另支持用户自建大类（孤儿子类自动补入「其他」）。
- **发现问题**：
  1. **分类结构存 localStorage**（groups/custom-subs/order/label-overrides 四组 key）：A 用户建的大类 B 用户看不到，但资料的 category 已写入数据库 → 多用户下分类视图割裂。
  2. 一次性拉全部知识文档 + 前端过滤分页，无服务端分页兜底。
  3. 大小限制**三处口径打架**：代码注释写 20MB、常量实际 200MB、帮助中心 FAQ 写 20MB。
  4. 上传成功后 `setTimeout(refetch, 3000)` 硬编码 3 秒刷新，索引状态时序脆弱。
  5. 同名校验按 fileName 全库唯一，跨分类也不允许同名。
  6. 移动分类弹窗写入格式 `${group}/${key}`，批量条写入 `knowledge/${key}` → **两处 category 存储格式不一致**。

### 3.4 方案库 Solutions（`/solutions`）

- **布局**：统计卡（5 卡）+ 左侧目录树（材料→厂名→机组→设备 四级，悬停可新建/排序/移动/重命名）→ 右侧 DataTable；新建编辑大弹窗、配置项/价格表子弹窗、详情抽屉。
- **表格列**：方案编号、方案名称、方案类型（标准/选配/定制模板）、适用产品线、版本、状态（草稿/已发布/已停用）。
- **表单字段**：方案名称*、方案类型、产品类型（按大类/子类分组可搜索）、状态、目录归属三段（材料/厂名/机组）、关键词标签、方案摘要、适用场景、关键参数（结构化编辑器）、参考价格区间、典型交付周期、CAD 模板地址、协议模板地址。详情内另有配置选项（key/label/choices/约束规则）与价格表（选项/价差/成本/交期/供应层级）子管理。

### 3.5 AI 助手 AIAssistant（`/ai-assistant`）

- **布局**：三栏——左侧会话历史；中间对话区（AI 在线状态 + 检索范围下拉 + 消息流 + 输入框）；右侧引用来源栏（可折叠）。
- **字段**：会话（title/messages/updatedAt）、消息（role/content/sources[]）、引用卡（类型标签、相关度百分比、摘要、跳转）。
- **操作**：新建/切换/删除会话、SSE 流式提问（携带最近 13 条历史）、停止生成、复制客户回复、重试、"保存为需求"、回答反馈、引用角标定位来源。
- **检索范围**：全部/客户/需求/方案/报价/产品/供应商/项目/文档（9 类）。
- **发现问题**：
  1. **会话与全部消息存 localStorage**，无后端持久化：换浏览器即丢，消息多有超配额风险。
  2. 每个流式 token 触发一次全量 `setSessions` 深拷贝，长回答渲染开销大。
  3. 请求直接用 `fetch + VITE_API_BASE_URL`，绕过 axios 拦截器与统一错误处理。
  4. 检索范围 9 类与引用来源支持的类型集（含 contract/ticket/knowledge）不一致。
  5. "重试"仅回填上一条提问到输入框，并非真正重放请求。

- **字段定义**：字段名 label、标识 key、类型、单位、必填、可选值、说明；分组固定优先序（来料信息/设备信息/成品参数/电源及公用工程/现场条件/配套选项）。

- **定位价值**：本模块的三级分类字符串是**产品分类与需求分类的共同源头**（Products 的分类下拉取自此处）。
- **发现问题**：
  1. 排序/展开偏好全部 localStorage，多端不一致。
  2. 分类不是独立实体（只是模板上的斜杠字符串），前端无法独立校验。

## 五、系统设置模块解读

### 5.1 系统信息 SystemInfo（`/settings`）

- **内容**：系统名称/版本/运行模式/运行状态 + AI 配置卡 + 数据导出入口。

  1. AI 配置卡三项（Embedding/LLM/索引状态）**全部硬编码静态文案**，与 AI 配置页实际配置可能不一致。
  2. "运行状态"恒为"正常"，接口失败也不反映。
  3. 版本号矛盾：登录页品牌面板写死 v2.0，本页显示后端返回的 0.1.0。

### 5.2 系统参数 SystemConfigPage（`/settings/config`）

- **内容**：键值对配置表（Key/值/分类/描述）+ 三个内联快捷编辑项（系统名称/副标题/管理员头衔）。
- **发现问题**：快捷项 Esc 取消与失焦保存存在交互冲突；搜索不匹配 value/description。

### 5.3 AI 配置 AiConfig（`/settings/ai`）

- **配置项**：三家 Provider（DeepSeek/GLM/OpenAI）的 apiKey/model/baseUrl；GLM 工具调用（function calling/联网搜索开关与引擎）；Ollama 本地降级；Embedding provider/model；RAG 参数（topK 1–50 / chunkSize 100–2000 / chunkOverlap 0–500）。
- **发现问题**：
  1. RAG 数字输入用 `parseInt(...) || 默认值`，清空或输 0 立即回弹默认值，无法自然编辑。
  2. 保存后 `invalidateQueries` 会用服务端数据覆盖本地未保存改动，无脏检查。
  3. 整页一个保存按钮全量提交，无"未保存改动"提示。

### 5.4 AI 预算 BudgetConfig（`/settings/budget`）

- **内容**：预警横幅 + 用量进度条 + 预算表单（月度预算/预警阈值/启用开关）+ 当期用量指标。
- **发现问题**（本页问题最集中）：
  1. **整页英文**（标题/按钮/toast），与全站中文风格割裂。
  2. **预警阈值是假控件**：UI 可编辑但 `handleSave` 只提交 monthlyLimit，改了不保存。
  3. **启用开关是死控件**：`onChange={() => {}}`，点了无任何反应。

### 5.5 编号规则 NumberingRules（`/settings/numbering`）

- **内容**：9 类单据（客户/需求/方案/报价/合同/项目/供应商/物料/售后工单）的前缀/年份格式/流水位数/分隔符行内编辑 + 实时预览 + 单据链式继承说明。
- **发现问题**：位数输入清空会得 NaN/0，无逻辑校验；"恢复默认"只改本地 state 需再点保存才生效但不提示。

### 5.6 回收站 RecycleBin（`/settings/recycle-bin`）

- **内容**：软删资料暂存列表（标题/分类/大小/删除时间/到期倒计时）+ 还原/彻底删除；保留 30 天。
- **边界说明**：仅资料类进回收站，主数据（客户/项目/报价）删除不进回收站——用户可能误以为一切可恢复。
- **发现问题**：无分页、无批量还原/清空。

### 5.7 备份还原 BackupRestore（`/settings/backup`）

- **内容**：创建备份（备注）+ 备份记录（下载/还原/删除）+ JSON 数据迁移；还原需输入确认词，重启后生效。
- **发现问题**：JSON 导入警告"请查看控制台"，普通用户无法获取；导入后全局作废缓存代价大。

### 5.8 使用效能 PerformanceMetrics（`/settings/metrics`）

- **内容**：AI 调用统计（调用数/成功率/耗时/Token）+ 知识健康度（解析覆盖率）+ 实体数量 + 近 7 天趋势 + 模块调用统计。
- **发现问题**：页面标题"使用与知识健康"与菜单"使用效能"不一致；Token 大数无单位换算。

### 5.9 操作记录 AuditLogs（`/settings/audit`）

- **内容**：服务端分页日志表（时间/动作/对象类型/对象 ID/用户 ID/IP/详情）+ 多条件筛选 + 详情抽屉（JSON 美化）。
- **发现问题**：动作/对象类型搜索无下拉候选需猜关键词；用户显示原始 userId 而非姓名；无日志导出。

### 5.10 登录页 Login（`/login`）

- **机制**：按后端模式自动选择——single 模式免密自动登录（退出后 sessionStorage 标记跳过）；team 模式账密表单（用户名/密码/记住用户名）；后端未就绪每秒重试最多 5 次。
- **发现问题**：版本号 v2.0 写死与系统信息页 0.1.0 不一致。

## 七、统一优化建议

> 以下建议基于全部页面代码解读 + 运行时验证统一给出，按优先级分四档：**P0 立即修复（功能性缺陷）→ P1 短期优化（数据一致性与体验）→ P2 中期改进（工程化）→ P3 长期演进（架构）**。

### P0 立即修复（功能性缺陷，影响使用正确性）

| # | 问题 | 建议 | 涉及 |
|---|---|---|---|
| P0-1 | 供应商比价死链：报价详情跳 `/suppliers/compare` 无路由 | 二选一：为 SupplierCompare 挂路由（如 `/suppliers/compare` 并入 SupplyTabs 第三个 Tab）；或删除按钮改跳物料 Tab | SupplierCompare、Quotations |

| P0-3 | 项目 dealStage 选项集两处不一致（表单 8 项不含 contract_signed，批量条含）；同阶段中文标签两处不同 | 将 dealStage 选项与文案收敛到 types 共享常量，单一来源 | Projects |

### P3 长期演进（架构级）

1. **后端列表接口返回结构统一**（消除 array/list/items 三种形状的兼容层），前端 extractList 兼容层退役。
2. **分类体系统一建模**：当前知识分类、资料分类、产品分类、参数模板分类四套体系各自为政（字符串路径 vs 选项常量 vs localStorage），建议抽象统一的分类实体 + 作用域，支撑跨模块检索与 team 模式共享。
3. **AI 洞察接口字段命名统一**（snake_case → camelCase，与全站一致）。
4. **审批流重建**：当前审批职能无入口（Approvals 死代码、合同仅单点审核）。若 team 模式是路线图，应设计统一的审批中心（单据类型 + 状态机），而非各单据散落实现。
5. **多币种支持**：供应商比价涉及 CNY/USD/EUR 混排，长期需汇率服务或至少按币种分组对比。
6. **视觉复核补做**：本文档基于代码级分析，受控浏览器窗口隐藏导致截图未能完成；建议后续窗口恢复后对 31 个页面补一轮截图复核（重点：Customer360 十页签、Documents 弹层矩阵、设置各页对齐样式）。
