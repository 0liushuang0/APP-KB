# 后续立项建议：ERP 集成 / CAD 图纸管理 / 移动端

> 定位：知识中心（ai-kb）交付后的二期立项储备。均依赖外部系统与业务优先级排期，本文作为立项输入材料，工作量级为季度评估。

## 一、ERP 集成（优先级建议：高）

**业务痛点**：客户/物料/合同数据在知识中心与 ERP 双头维护，报价 BOM 无法直接转 ERP 采购/生产指令，回款状态要人工对账。

**范围建议（按阶段）**：
1. **主数据同步**（客户、物料）：ERP 为主、知识中心为从，单向或双向按字段定主数据Owner。物料编号对齐（见《编号规则定版》核对点④）。
2. **合同→ERP 订单**：合同列表推送生成 ERP 销售订单，回写 ERP 单号到合同档案。
3. **回款对账**：ERP 收款流水回写合同的应收/实收台账（现有「导出应收」的自动化版）。

**依赖**：ERP 厂商开放 API 或中间表（金蝶/用友/SAP 均有集成方案）；网络打通（内网或专线）。

**风险**：主数据双写冲突——需先定字段级 Owner，否则集成后反而脏数据增多。

## 二、CAD 图纸管理（优先级建议：中）

**业务痛点**：技术方案/项目交付涉及大量 DWG/DXF 图纸，目前只能作为附件存档，无法在线预览、无法按图号检索、版本靠文件名区分。

**范围建议**：
1. **图纸在线预览**：DXF 转 SVG 服务端渲染（ezdxf 方案已调研，安装受阻待重试；DWG 需 ODA 转换器或 Teigha，商业授权需评估）。
2. **图号结构化**：图纸档案按 图号-版本 管理，与产品型号/项目关联（复用 document_links 模型）。
3. **CAD 端插件（选配）**：AutoCAD 插件一键上传当前图纸到对应项目（依赖 CAD 二次开发，工作量另评）。

**依赖**：DWG 预览的商业组件选型；图纸密级管控策略（涉密图纸是否允许服务端解析）。

## 三、移动端（优先级建议：中）

**业务痛点**：出差/现场（售后工程师、销售拜访）无法随手查资料、录跟进、拍照上传现场照片。

**范围建议**：
1. **PWA 优先**（不进应用商店）：响应式适配 + manifest + 拍照上传（`<input capture>`），覆盖 80% 现场场景，成本最低。
2. **企业微信/钉钉集成**（选配）：登录打通 + 消息推送（待办/审批/跟进提醒推到工作群）。
3. **原生 App**（远期）：仅当 PWA 无法满足（离线作业、扫码、定位打卡）再立项。

**依赖**：外网访问通道（当前系统内网部署，需 HTTPS 网关或 VPN）；推送通道选型。

## 四、立项顺序建议

ERP 主数据同步（消除双头维护）→ PWA 移动端（低门槛高感知）→ CAD 预览 → ERP 单据级集成 → 原生 App。每项建议单独立项，先出 2 周内的技术验证 PoC 再排期。
