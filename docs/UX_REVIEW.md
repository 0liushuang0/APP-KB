# 前端体验审计：导航 / 布局 / 视觉 / 交互 / 可用性

> 对象：博亚精工 AI 业务知识库前端（frontend/src，9925 行，29 个页面）
> 评审基准：系统的两个核心用途 —— **交流回答问题**、**快速出方案**
> 日期：2026-08-01

---

## 0. 一句话结论

**系统被建成了"业务对象的管理后台"，而不是"业务流程的工作台"。**

24 个导航项按 `客户 / 需求 / 方案 / 报价 / 产品 / 供应商` 这样的**数据表**组织，
但技术员和市场部每天做的是一条**流水线**：接需求 → 理参数 → 找相似方案 → 算配置 → 查价 → 出报价。

现在的界面要求他们自己在 6 个模块之间来回跳，自己记住"我做到哪一步了"。
功能是齐的，**动线是断的**。这是本次审计发现的最主要问题，也是"提效"目标最大的折损点。

其余问题按严重度排在后面，包含我自己在 P0–P6 里留下的几处不一致。

## 1. 导航与信息架构

### 1.1 现状

五大主区 / 24 个二级项：

| 主区 | 项数 | 项 |
|------|-----|-----|
| 工作台 | 2 | 仪表盘、审批中心 |
| 业务管理 | 5 | 客户、需求、方案、报价、项目 |
| 知识中心 | 5 | 文档中心、方案模板库、供应商管理、计算工具、知识问答 |
| 产品管理 | 3 | 产品库、产品分类、参数模板 |
| 系统设置 | 9 | 用户、角色、部门、用户组、审批流、系统参数、AI配置、审计日志、效能看板 |

### 1.2 问题

**🔴 P1｜知识问答被埋在第 3 主区第 5 项**

系统的头号用途是"交流回答问题"，但它在导航里的位置和"文档中心""供应商管理"完全平级，
要滚到知识中心分组的末尾才能点到。

这是**信息架构与业务目标的错位**。客户在电话里问"你们矫直机最大能做多宽"，
销售需要的是 1 秒唤起，而不是"展开知识中心→找到第 5 项→点击→等页面加载"。

**🔴 P1｜没有流程视图，动线全靠人脑记忆**

`需求 → 方案 → 报价` 是一条链，但界面上没有任何地方能看到这条链的当前状态。
`projects` 表里有 `dealStage` 八态字段（需求登记/需求识别/方案编制/报价编制/报价审核/已提交/已成交/已流失），
**这个字段没有任何页面把它画成流程条**。数据在，视图没有。

**🟡 P2｜24 项对单个角色都太多**

技术员不需要看报价管理和系统设置的 9 项；市场部不需要看参数模板和计算工具。
现在所有人看到同一份 24 项菜单，`teamOnly` 只区分了单人/团队模式，**没有按角色裁剪**。

**🟡 P2｜产品分类与产品库功能重复**（我引入的）

`Products.tsx` 本身就是「260px 分类树 + 右侧详情」的三栏布局，自带分类树。
我又新增了 `ProductTree.tsx`（201 行）挂到"产品分类"菜单，做了一棵几乎一样的树。
**同一件事两个入口**，用户会困惑该点哪个。

### 1.3 建议

```
工作台        我的工作台（流程看板）· 审批中心
业务流程      需求受理 → 方案编制 → 报价提交   ← 按阶段而非按表组织
业务档案      客户 · 项目 · 历史方案 · 历史报价
知识助手      ⭐ 智能问答（置顶）· 资料中心 · 供应商 · 计算工具 · 方案模板
产品与标准    产品库（含分类树）· 参数模板
系统设置      收进右上角头像菜单，不占主导航
```

关键动作：
1. **知识问答提到导航第一屏**，并在顶栏常驻一个提问入口（不止 ⌘K 搜索）
2. **合并产品分类进产品库**，删掉重复菜单项
3. **系统设置 9 项移出主导航**，进头像下拉 —— 日常业务用不到
4. **按角色裁剪菜单**：技术员 / 市场部 / 技术领导 / 管理员 四套预设

## 2. 布局一致性

### 2.1 现状盘点（实测）

| 页面 | 列表 | 详情形态 | 左筛选 | 标签页 |
|------|-----|---------|-------|-------|
| 需求管理 | 表格 | **独立路由**（6 标签页） | ✗ | ✓ |
| 方案管理 | 表格 | 抽屉 520px | ✗ | ✗ |
| 报价管理 | 表格 | 抽屉 560px | ✗ | ✗ |
| 项目管理 | 表格 | 抽屉 | ✗ | ✗ |
| 客户管理 | 表格 | 抽屉 + 独立 360 页 | ✗ | ✗ |
| 供应商 | 表格 | 抽屉 720px | ✓ | ✓ |
| 资料中心 | 表格 | 抽屉 560px | ✓ | ✗ |
| 产品库 | **三栏树** | 内嵌 | 树 | ✗ |
| 方案模板库 | 表格 | 抽屉 | ✗ | ✗ |

### 2.2 问题

**🔴 P1｜同一层级的业务对象，详情形态三种做法**

我在 P5 把需求详情升级成独立路由 + 标签页（因为矫直需求卡有 40+ 参数），
但**方案、报价、项目仍停在 520px 抽屉**。

结果是：用户点"需求"进全屏页，点"方案"弹小抽屉，点"产品"进三栏树。
**同样是"看一条记录的详情"，三次交互心智模型完全不同**。这是我这轮改造留下的最明显的不一致。

方案详情尤其吃亏 —— 它要装 CAD 图纸、技术协议、BOM 清单、关联报价、历史匹配五块内容，
520px 抽屉根本放不下，现在只能显示前两块。

**🟡 P2｜只有 2/9 的列表页有左侧筛选**

资料中心和供应商有六维筛选面板，其余 7 个列表页仍是"顶部一个搜索框 + 一个下拉"。
需求列表连按客户筛选都没有 —— 而"这个客户历史提过什么需求"是高频问法。

**🟡 P2｜表格列数偏多**

供应商 13 列、资料中心 12 列、比价 8 列。1280px 下必然横向滚动。
策划文档自己写的原则是"列表只展示最关键的 4-5 个字段"，实际做成了 13 列。

### 2.3 建议

| 对象 | 应有形态 | 理由 |
|------|---------|------|
| 需求 / 方案 / 报价 / 项目 | **统一独立路由 + 标签页** | 字段多、要挂附件、要看关联 |
| 客户 | 独立路由（360 视图，已有） | 保持 |
| 供应商 / 资料 / 产品 | 抽屉即可 | 字段少，不打断列表操作 |

- 把 `DetailLayout` 组件（P1 已建）推广到方案 / 报价 / 项目三页
- 把 `FilterPanel` 组件（P1 已建）推广到需求 / 方案 / 报价 / 项目四页
- 表格默认列收敛到 6 列以内，其余走「列设置」抽屉让用户自选

## 3. 视觉与色彩

### 3.1 现有设计语言

```
字体   Fraunces（衬线标题）+ Inter（正文）+ JetBrains Mono（数字/编号）
主色   accent 橙 #ff5b1f
底色   canvas 米白 #f7f6f2 · surface #fff · subtle #faf9f6
侧栏   深蓝灰 #161b26 → #1e2330 渐变
状态   success/warning/danger/info/neutral 五组语义色
图表   viz 1-5 分类色（已过色觉安全校验）
```

**这套语言是有辨识度的，不像通用管理后台**，这点值得保留。
深色侧栏 + 米白内容区的对比也符合长时间使用的舒适度要求。

### 3.2 问题

**🟡 P2｜110 处原始调色板未收敛**（我 P1 没做完）

P1 我只迁移了 `slate-*` 和 `primary-*`，遗漏了 red/green/blue/amber/purple 等：

| 残留 | 次数 | 集中在 |
|------|-----|-------|
| `text-red-600 / -700` | 49 | 各页删除按钮 |
| `text-green-600` | 10 | 状态文字 |
| `bg-blue-50 / bg-amber-50` | 8 | 参数模板、客户360 |
| 其他 | ~43 | ParamTemplates(17)、Customer360(13) |

后果：同一个"危险"语义在不同页面是 `text-red-600`、`text-red-700`、`text-danger-fg` 三种值，
将来要调品牌色得改 110 处。

**🟡 P2｜两套字号体系并存**

- 任意值 `text-[13px]` 等：**262 处，12 种不同尺寸**
- 语义值 `text-sm/xs/lg`：**314 处**

`text-sm`(14px) 和 `text-[13px]` 在同一个卡片里混用，视觉上是"差一点点但说不清哪不对"。

**🟢 P3｜衬线标题在工程语境下略显文艺**

Fraunces 用在"工作 台""供应商 管理"这类标题上，气质偏编辑/杂志。
对装备制造业的内部系统，可以考虑标题也用 Inter Semibold，把衬线只留给仪表盘的大数字。
这条是审美判断，非硬伤 —— 若品牌层面认可当前调性，保留即可。

### 3.3 建议

1. 补完 token 迁移：`red-*`→`danger-*`、`green-*`→`success-*`、`amber-*`→`warning-*`、`blue-*`→`info-*`
2. 冻结字号刻度为 6 档并写进 `index.css`：
   `10px 标注 / 11px 标签 / 13px 正文 / 15px 小标题 / 19px 页内标题 / 28px 页标题`
   禁止再出现新的任意值
3. 删除未定义的 `eo-scroll` 类（Products.tsx 在用，但 CSS 里只定义了 `eo-scroll-dark` 和 `eo-scroll-x`，
   目前这个类**不产生任何样式**）

## 4. AI 能力的暴露度 —— 最大的价值浪费

### 4.1 实测：后端有的能力，前端用了多少

| AI 能力 | 后端 | 前端暴露位置 |
|---------|-----|------------|
| 需求结构化解析 | ✓ | 需求详情 ✓ |
| 补问草稿（微信/邮件） | ✓ | 需求详情 ✓ |
| 相似方案匹配 | ✓ | 需求详情 ✓ |
| 方案 AI 生成 | ✓ | 方案页 ✓ |
| 报价建议 | ✓ | 报价页 ✓ |
| 知识问答 | ✓ | 问答页 ✓ |
| **参数 diff 对比** | ✓ | **❌ 无任何入口** |
| **RAG 原文检索** | ✓ | **❌ 无任何入口** |

**🔴 P1｜行内问答只挂在 2 个页面**

`AssistantWidget`（页内浮动问答）只出现在**参数模板**和**方案模板库**两个页面 ——
恰恰是用户待得最少的两页。

而真正需要"边做边问"的地方：
- 需求详情页（这个参数客户没给，历史上一般取多少？）
- 报价页（这个件上次给这个客户报多少？）
- 方案页（类似工况我们做过没有？）

**这三个页面一个都没有。**

**🔴 P1｜参数 diff 写好了却没入口**

`matchingApi.paramDiff` 能算出"当前需求 vs 历史方案"的参数差异表 ——
这正是"快速出方案"的关键：找到最像的历史方案，只改不同的那几项。
后端完整实现，前端零调用。

### 4.2 建议

1. **AssistantWidget 挂到需求 / 方案 / 报价三个详情页**，并把当前记录作为上下文传入
   （问"这个参数一般取多少"时，AI 知道你在看哪条需求）
2. **在"历史相似方案"列表每行加「参数对比」按钮**，调 `paramDiff` 弹出差异表，
   绿色=一致、橙色=需调整，让技术员一眼看出改哪几项
3. **顶栏加常驻提问框**：现在 ⌘K 是关键词搜索，应支持"直接问"模式（回车走 RAG 问答）

## 5. 交互与可用性

### 5.1 关键场景的操作成本（实测点击数）

**场景 A：客户电话问"矫直机能做多宽的板"**
```
现状：展开知识中心(1) → 点知识问答(2) → 输入(3) → 回车(4)   = 4 步 + 一次页面切换
理想：⌘K → 输入 → 回车                                      = 1 步，不离开当前页
```

**场景 B：收到客户询价 → 出方案**
```
现状：需求管理 → 新建需求 → 填表 → 保存 → 进详情 → 上传资料 →
     结构化识别 → 看参数 → 发现缺项 → 生成补问 → 复制发客户 →
     （等回复）→ 改参数 → 关联方案 → 跳方案页 → 新建 → 填表 …
     ≈ 18 步，跨 3 个页面，全程无进度指示
```

场景 B 是"快速出方案"的主路径，现在**没有任何引导**。用户必须自己知道下一步该干什么。

### 5.2 其他可用性问题

**🟡 P2｜列表页没有批量操作**
9 个列表页都没有多选。市场部要批量导出 20 条报价、技术部要批量归档需求，只能一条条点。

**🟡 P2｜没有"最近访问"**
用户每天反复打开同几条需求/方案，每次都要重新搜索定位。

**🟡 P2｜平板适配不足**
响应式断点使用：`md:` 76 处、`lg:` 41 处、`sm:` 仅 9 处、`xl:` 仅 3 处。
另有 20+ 处 `w-[520px]`～`w-[720px]` 固定宽抽屉，在 768px 平板上会占满甚至溢出。
策划文档要求"列表、表单、详情页均支持平板访问"，目前只能算勉强可用。

**🟢 P3｜键盘可达性已达标**
P1 加的全局 `focus-visible` 焦点环 + `prefers-reduced-motion` 已覆盖；
表单 label 关联、`aria-label`、`aria-invalid` 基本齐全。这块无需返工。

## 6. 数据可视化

### 6.1 现状

仅工作台有两张图：转化漏斗（横向条）+ 近 6 个月报价额（柱状）。
viz 1-5 分类色已通过色觉安全校验（亮度带 / 彩度 / CVD 相邻区分 / 对比度五项）。

### 6.2 缺口

| 场景 | 该有的图 | 现状 |
|------|---------|-----|
| 供应商价格趋势 | 折线（同一产品历年报价） | ❌ 后端 `price-history` 已有，前端未画 |
| 客户 360 | 业务量时间线 / 金额构成 | ❌ 只有数字卡片 |
| 参数完整度 | 环形进度 | 🟡 只有一条细进度条 |
| 报价成本构成 | 堆叠条（成本/毛利） | ❌ 只有三个数字 |
| 项目阶段分布 | 漏斗按阶段计数 | ❌ 无 |

**🟡 P2｜"专业感"没有通过可视化传达**

策划文档提到计算工具的价值之一是"展示专业能力"。
现在计算结果是一张纯数字表 —— 而矫直力沿辊列的分布曲线、剪切力随板厚的变化曲线，
这类图恰恰是客户会觉得"这家供应商真懂"的东西。

## 8. 需要业务侧确认的三件事

1. **主导航要不要按角色裁剪？** 若要，需确认技术员/市场部/技术领导各自的菜单范围。
2. **衬线标题（Fraunces）保留还是换成无衬线？** 这是品牌调性决策，不是技术问题。
3. **"快速出方案"的目标动线是什么？** 现在系统假设是"先建需求再建方案"，
   但如果实际业务常见"老客户直接照上次的改"，那入口应该是"从历史方案复制"而非"新建需求"。
   这条会显著改变第 1 项的设计。
